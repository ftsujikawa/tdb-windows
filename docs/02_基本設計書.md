# tdb-windows 基本設計書

## 1. 目的

本書は、「01_要件定義書.md」で定義した要件を実現するための、tdb-windows のシステム構成・モジュール分割・外部インタフェース(コマンド仕様)・主要データ構造・処理方式の概要を定義する。

## 2. システム構成

### 2.1 全体構成

tdb-windows は単一の実行ファイル(コンソールアプリケーション)であり、外部プロセスとの通信は Win32 デバッグ API を介した OS 標準の仕組みに限定される。

```
+-------------------------------------------------------------+
|                      tdb-windows.exe                         |
|                                                               |
|  +--------+   +-----------+   +---------------------------+ |
|  | main   |-->| Debugger  |-->| commands (コマンド解析)     | |
|  | (REPL) |   | (中枢制御)|   +---------------------------+ |
|  +--------+   |           |-->| process  (Win32デバッグ層)  | |
|                |           |-->| breakpoint / watchpoint     |
|                |           |-->| symbols  (DbgHelp)          |
|                |           |-->| eval     (式パーサ/評価器)  |
|                |           |-->| disasm   (逆アセンブラ)     |
|                +-----------+   +---------------------------+ |
+-------------------------------------------------------------+
              | CreateProcess / WaitForDebugEvent /
              | ReadProcessMemory / SetThreadContext 等
              v
+-------------------------------------------------------------+
|      デバッギー(ルートプロセス)  --(CreateProcess)-->  子プロセス  |
|                                                --> 孫プロセス...   |
+-------------------------------------------------------------+
```

### 2.2 モジュール一覧

| モジュール(ファイル) | 役割 |
|---|---|
| `main.rs` | エントリポイント。コマンドライン引数解析(clap)、Ctrl+C ハンドラ登録、`SeDebugPrivilege` 有効化、`Debugger` 生成と REPL 起動。 |
| `debugger.rs` | 中枢制御。`Debugger` 構造体がアプリケーション状態(プロセス・ブレークポイント・ウォッチポイント・スレッド一覧・print 設定等)を保持し、REPL から受け取ったコマンドを処理し、デバッグイベントループ(`continue_execution`)を実行する。 |
| `commands.rs` | REPL 入力文字列を `Command` 列挙型へ変換するパーサ、およびヘルプテキスト。 |
| `process.rs` | Win32 デバッグ API の薄いラッパー層。プロセス起動(`DebuggeeProcess::launch`)、複数プロセスのハンドル管理、メモリ読み書き、ソフトウェアブレークポイントの設置/解除、スレッドコンテキスト取得/設定、デバッグレジスタ操作、Ctrl+C 転送、`SeDebugPrivilege` 有効化。 |
| `breakpoint.rs` | ソフトウェアブレークポイントの管理(`(pid, address)` をキーとする一覧・追加・削除)。 |
| `watchpoint.rs` | ハードウェアウォッチポイント(DR0-DR3/DR7)の管理(4 スロット、`pid` を保持)。 |
| `symbols.rs` | DbgHelp (`dbghelp.dll`) ラッパー。モジュールロード、シンボル解決(アドレス⇔名前)、型情報取得、スタック巻き戻し、ローカル/グローバル変数列挙。 |
| `eval.rs` | C 言語類似の式の字句解析・構文解析・評価器。デバッギーのメモリ/レジスタ/型情報へのアクセスは `EvalContext` トレイト経由で抽象化。 |
| `disasm.rs` | `iced-x86` を用いた x64 命令デコード・逆アセンブル整形。 |
| `error.rs` | `DebuggerError` (thiserror ベース)。Win32 エラー、コマンド不正、対象未検出等を表現。 |

## 3. 処理方式概要

### 3.1 起動からコマンド処理までの流れ

1. `main.rs` がコマンドライン引数から対象実行ファイルと引数を取得。
2. 割り込みハンドラ登録 (`process::install_interrupt_handler`) と `SeDebugPrivilege` 有効化 (`process::enable_debug_privilege`) を行う。
3. `Debugger::new` でアプリケーション状態を初期化し、`run_repl` を呼び出す。
4. REPL ループ: 標準入力から 1 行読み込み → `commands::parse` で `Command` に変換 → `Debugger::handle_command` に委譲 → 結果(継続/終了)に応じてループを継続または終了。

### 3.2 デバッグイベントループ

`run` または `continue` コマンドが実行されると `Debugger::continue_execution` が呼び出され、以下をブロッキングではなくポーリング(タイムアウト付き `WaitForDebugEventEx`)で繰り返す。

1. Ctrl+C 転送要求(`process::take_interrupt_requested`)を確認し、要求があればデバッギーへ転送。
2. デバッグイベントを待機(タイムアウト時は 1. に戻る)。
3. `event.dwProcessId` / `event.dwThreadId` を「今回のイベントを発生させたプロセス/スレッド」として `self.last_thread_id` 等に反映。
4. イベント種別(`dwDebugEventCode`)に応じて分岐処理(詳細は「03_詳細処理設計書.md」参照)。
5. 処理の結果、REPL に制御を返す(停止理由を表示して戻る)か、`ContinueDebugEvent` を呼び出しループを継続するかを決定する。

### 3.3 マルチプロセス/マルチスレッド設計方針

- プロセス起動時のフラグを `DEBUG_PROCESS` とすることで、ルートプロセスだけでなく、その子孫プロセスすべてを Windows のデバッグ API 経由で捕捉する。
- `DebuggeeProcess` はルートプロセスの PID (`root_pid`) と、`pid -> (ハンドル, メインスレッドID, ビット数)` のマップを保持し、複数プロセスのハンドルを一元管理する。
- `Debugger` はスレッド ID からプロセス ID を引けるマップ (`threads: HashMap<スレッドID, プロセスID>`) を保持し、「カレントスレッドが属するプロセス」を `current_pid()` として導出する。ブレークポイント設置(生アドレス指定時)・メモリダンプ・式評価・逆アセンブルは、原則としてこの `current_pid()` を対象とする。
- デバッグイベントループ内では、イベント自身が保持する `event.dwProcessId` を常に正とする(スレッド→プロセスのマップがまだ反映されていないタイミング、たとえばプロセス生成直後のイベントでも矛盾なく解決できるため)。
- シンボル解決(DbgHelp)はルートプロセスのプロセスハンドルに対してのみ初期化・利用する。DbgHelp のシンボルセッションはプロセスごとに独立しており、子プロセス分もサポートするには別途プロセスごとのリソースが必要となるため、本バージョンでは意図的にルートプロセスへ限定する(要件定義書 6 章参照)。この方針に基づき、シンボル名解決を伴う機能(`break <シンボル>`、`break <ファイル:行>`、`leak start` のアロケータ関数解決、バックトレース、ソース表示)はルートプロセスのスレッドを対象に使う場合にのみ意味のある結果となる。
- プロセス終了イベント (`EXIT_PROCESS_DEBUG_EVENT`) 受信時、当該 PID がルートプロセスか否かで処理を分岐する。ルートプロセスの場合はセッション終了(`shutdown`)。子プロセスの場合は当該プロセスの追跡情報のみを削除し、セッションは継続する。

## 4. 主要データ構造

### 4.1 `Debugger` (debugger.rs)

アプリケーション全体の状態を保持する中心的な構造体。主なフィールドを示す。

| フィールド | 型(概要) | 役割 |
|---|---|---|
| `process` | `Option<DebuggeeProcess>` | 現在デバッグ中のプロセス群(未起動時は `None`)。 |
| `breakpoints` | `BreakpointManager` | ソフトウェアブレークポイント一覧。 |
| `watchpoints` | `WatchpointManager` | ハードウェアウォッチポイント一覧(最大 4)。 |
| `threads` | `HashMap<u32, u32>` | スレッド ID → 所属プロセス ID。 |
| `locked_thread` / `frozen_threads` | `Option<u32>` / `HashSet<u32>` | `lock`/`unlock` の状態。 |
| `symbols` | `Option<SymbolResolver>` | ルートプロセスに対するシンボル解決器。 |
| `last_thread_id` | `u32` | カレントスレッド。 |
| `print_settings` | `PrintSettings` | `set print` 設定値。 |
| `leak_hooks` / `allocations` 等 | - | メモリリーク検出用の内部状態。 |

### 4.2 `DebuggeeProcess` (process.rs)

| フィールド | 型 | 役割 |
|---|---|---|
| `root_pid` | `u32` | ルートプロセスの PID。 |
| `processes` | `HashMap<u32, ProcessEntry>` | PID → { プロセスハンドル, メインスレッドハンドル/ID, 64bit 判定 }。ルート・子プロセス双方を含む。 |

### 4.3 `Breakpoint` (breakpoint.rs) / `Watchpoint` (watchpoint.rs)

| 構造体 | 主キー | 主なフィールド |
|---|---|---|
| `Breakpoint` | `(pid, address)` | `id`, `pid`, `address`, `original_byte`(退避した元のバイト値), `enabled` |
| `Watchpoint` | スロット番号(0-3) | `id`, `pid`, `expr`, `address`, `size`, `kind`(Write/Access), `last_value` |

## 6. エラー処理方針

- Win32 API 呼び出しの失敗は `DebuggerError::Windows` としてラップし、REPL 層で捕捉して `Error: ...` を標準エラー出力へ表示し、REPL 自体は継続する。
- コマンド解析エラー(引数不足・不正値)は `DebuggerError::InvalidCommand` とし、同様に継続可能なエラーとして扱う。
- デバッグイベントループ内で発生しうる「一部スレッドへのアクセス拒否」等、想定内かつ個別スレッドに閉じたエラーは、ループ全体を止めずに警告出力のみで継続する(該当スレッドへの操作をスキップする)。これは `ContinueDebugEvent` を呼び出す前に致命的エラーで抜けてしまうと、当該デバッグイベントが未応答のままデバッギー全体が停止し続けるため。
- プロセス未起動時のコマンド実行は、多くの場合「No process is running.」を出力してコマンドを無視する形とし、異常終了はさせない。

## 7. 制約・前提条件

- 本設計は x64 デバッギーのみを前提とする。
- `SeDebugPrivilege` は「有効化を試みるが失敗しても継続する」設計とし、非管理者権限での実行を妨げない。
- シンボル関連機能はルートプロセスに限定する(4 章参照)。
