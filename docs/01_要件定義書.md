# tdb-windows 要件定義書

## 1. 文書の目的

本書は、Windows 用の小規模コマンドラインデバッガ「tdb-windows」が満たすべき要件を定義する。対象読者は本ソフトウェアの開発・保守・テストに関わる技術者とする。

## 2. システム概要

tdb-windows は、Rust で実装された Windows x64 向けのユーザーモードデバッガである。Win32 デバッグ API(`CreateProcess` + `WaitForDebugEvent`/`ContinueDebugEvent` 系)を直接利用し、対話的な REPL(コマンドライン)から対象プログラム(デバッギー)の実行制御、ブレークポイント/ウォッチポイント設置、レジスタ・メモリ参照、C 言語式評価、シンボル解決、簡易メモリリーク検出などを行う。GDB / WinDbg に類似したコマンド体系を採用する。

## 3. 用語定義

| 用語 | 説明 |
|---|---|
| デバッガ | tdb-windows 自身のプロセス |
| デバッギー | tdb-windows がデバッグ対象として起動したプロセス(ルートプロセス)、および、その子孫として生成され同様にデバッグ対象となるプロセス |
| ルートプロセス | `run` コマンドでデバッガが直接 `CreateProcessW` により起動した最初のプロセス |
| 子プロセス | ルートプロセス(またはその子孫)が `CreateProcess` 系 API で生成し、Windows デバッグ API 経由でデバッガに通知される派生プロセス。孫プロセス以降も同様に扱われる |
| カレントスレッド/カレントプロセス | `thread <id>` で選択中のスレッド、およびそのスレッドが属するプロセス。レジスタ表示・メモリ操作・式評価・ブレークポイント設置(生アドレス指定時)等の既定の対象となる |
| ソフトウェアブレークポイント | 対象アドレスの先頭バイトを `INT3` (0xCC) に書き換えることで実現する実行停止機構 |
| ハードウェアウォッチポイント | x64 デバッグレジスタ (DR0-DR3, DR7) を用いた、メモリ読み書き検知によるブレーク機構 |
| シンボル | DbgHelp (`SymInitializeW` 等) を通じて PDB から取得する関数名・変数名・型情報・ソース行対応情報 |

## 4. 機能要件

### 4.1 プロセス制御

| ID | 要件 |
|---|---|
| F-PROC-01 | コマンドライン引数で指定された実行ファイルおよび引数を、デバッグ対象として起動できること(`run`)。 |
| F-PROC-02 | プロセス起動時に `DEBUG_PROCESS` フラグを用い、デバッギーが生成する子プロセス・孫プロセスも継続してデバッグ対象に含めること。 |
| F-PROC-03 | 起動済みのデバッギーに対し、実行継続(`continue`)ができること。 |
| F-PROC-04 | 既に実行中のデバッギーが存在する状態で `run` が実行された場合、既存のデバッギーを終了し再起動すること。 |
| F-PROC-05 | ルートプロセスの終了を検知した場合、デバッグセッション全体を終了状態にすること。 |
| F-PROC-06 | 子プロセス(孫プロセス以降を含む)の終了を検知した場合、当該プロセスの追跡のみを解除し、デバッグセッション全体は継続すること。 |
| F-PROC-07 | 追跡中の全プロセス(ルート・子)を一覧表示できること(`processes` / `ps`)。一覧には PID、メインスレッド ID、ルート/子の区別を含むこと。 |
| F-PROC-08 | デバッガ終了時、または新規 `run` 時に、それまで追跡していた全プロセスのハンドルを解放し、必要に応じてプロセスを終了させること。 |
| F-PROC-09 | Ctrl+C 入力をデバッガ自身ではなくデバッギー(ルートプロセス)に転送できること。 |
| F-PROC-10 | プロセスの 32/64bit 判別(WOW64 判定)を行うこと(情報保持のみで表示等への利用は必須としない)。 |

### 4.2 ブレークポイント

| ID | 要件 |
|---|---|
| F-BP-01 | アドレス(16進/10進)、シンボル名(関数名)、`ファイル名:行番号` のいずれの指定でもソフトウェアブレークポイントを設置できること(`break`)。 |
| F-BP-02 | シンボル名・`ファイル名:行番号` によるアドレス解決は、ルートプロセスのシンボル情報に基づいて行うこと。 |
| F-BP-03 | 生アドレス指定によるブレークポイントは、カレントプロセス(カレントスレッドが属するプロセス)に対して設置されること。これにより子プロセスへのブレークポイント設置も可能とする。 |
| F-BP-04 | 設置済みブレークポイントを番号指定で削除できること(`delete`)。 |
| F-BP-05 | 設置済みブレークポイントの一覧(番号、アドレス、対象 PID、有効/無効、シンボル情報)を表示できること(`breakpoints` / `bl`)。 |
| F-BP-06 | ブレークポイントにヒットした場合、実行を停止し、停止位置のソースまたは逆アセンブル、レジスタ等を表示すること。 |
| F-BP-07 | 同一アドレス値であっても、異なるプロセスに設置されたブレークポイントは独立して管理されること。 |

### 4.3 ウォッチポイント

| ID | 要件 |
|---|---|
| F-WP-01 | C 言語式(変数・メンバ・配列要素等)を指定し、書き込み時に停止するウォッチポイントを設置できること(`watch`)。 |
| F-WP-02 | 読み書き両方で停止するウォッチポイント(アクセスウォッチポイント)を設置できること(`awatch` / `rwatch`)。 |
| F-WP-03 | ハードウェアデバッグレジスタは 4 スロットのみのため、同時に設置可能なウォッチポイントは最大 4 件に制限されること。上限超過時はエラーメッセージを表示すること。 |
| F-WP-04 | 監視対象が 1/2/4/8 バイトに収まらない場合はウォッチポイントを設置できない旨を通知すること。 |
| F-WP-05 | ウォッチポイントは、設置対象プロセス内の全スレッドに同期されること。当該プロセス以外のスレッドには影響しないこと。 |
| F-WP-06 | ウォッチポイントにヒットした場合、旧値・新値(可能な場合)、停止位置を表示すること。 |
| F-WP-07 | 設置済みウォッチポイントを番号指定で削除できること(`deletewatch` / `dw`)。 |
| F-WP-08 | 設置済みウォッチポイントの一覧を表示できること(`watchpoints` / `wl`)。 |
| F-WP-09 | 新規スレッド生成時、既存の有効なウォッチポイントのうち当該スレッドが属するプロセスのものだけを、そのスレッドのデバッグレジスタへ反映すること。 |

### 4.4 実行制御(ステップ実行)

| ID | 要件 |
|---|---|
| F-STEP-01 | 現在のカレントスレッドに対し、1 命令単位のステップイン実行ができること(`step`)。 |
| F-STEP-02 | 現在のカレントスレッドに対し、CALL 命令をまたいで実行するステップオーバー実行ができること(`next`)。 |
| F-STEP-03 | ステップ実行中、同一ソース行にとどまる限りは自動的にステップを継続し、行が変わった時点で停止すること。 |
| F-STEP-04 | 現在の関数からの復帰(呼び出し元への復帰)まで実行を継続できること(`finish` / `up`)。 |

### 4.5 スレッド管理

| ID | 要件 |
|---|---|
| F-TH-01 | デバッグ対象(ルート・子プロセスを含む)の全スレッドを一覧表示できること(`threads`)。一覧には所属 PID、メインスレッド表示、カレントスレッド表示、ロック/フリーズ状態を含むこと。 |
| F-TH-02 | カレントスレッドを切り替えられること(`thread <id>`)。切り替えは以後のレジスタ表示・逆アセンブル・バックトレース・式評価・メモリ操作・生アドレスブレークポイント設置の対象に反映されること。 |
| F-TH-03 | 指定した(または現在の)スレッドのみ実行を許可し、それ以外の全スレッドを一時停止(フリーズ)できること(`lock`)。 |
| F-TH-04 | `lock` による全スレッドフリーズを解除できること(`unlock`)。 |
| F-TH-05 | `lock` 実行後に生成された新規スレッドは、自動的にはフリーズ対象に含めないこと。 |
| F-TH-06 | ロック中のスレッドが終了した場合、ロックを自動解除し、フリーズ中の他スレッドを再開すること。 |
| F-TH-07 | デバッガによるコンテキスト取得・サスペンドが拒否される(アクセス拒否)スレッドが存在しても、デバッグループ全体が停止・異常終了しないこと。 |

### 4.6 レジスタ・メモリ・逆アセンブル

| ID | 要件 |
|---|---|
| F-MEM-01 | カレントスレッドの汎用レジスタ・EFLAGS・MXCSR・MMX/x87・XMM レジスタを表示できること(`registers` / `regs`)。 |
| F-MEM-02 | 指定アドレスからの任意バイト数のメモリダンプを表示できること(`memory` / `x`)。対象はカレントプロセスとすること。 |
| F-MEM-03 | 指定アドレス・シンボル・`ファイル:行番号`、または現在位置からの逆アセンブル表示ができること(`disassemble` / `dis`)。 |
| F-MEM-04 | カレントスレッドのコールスタック(バックトレース)を表示できること(`backtrace` / `bt`)。 |
| F-MEM-05 | 現在位置(または指定位置)のソースコード、もしくはソース情報が無い場合は逆アセンブルを表示できること(`list` / `l`)。 |

### 4.7 式評価・変数表示

| ID | 要件 |
|---|---|
| F-EXPR-01 | C 言語に類似した式(四則演算、剰余、ビット演算、比較演算、単項演算子 `- + ! ~ * &`、メンバアクセス `. ->`、配列添字 `[]`)を解釈・評価できること。 |
| F-EXPR-02 | 変数名・レジスタ名(`$rax` 等)を式中で参照できること。 |
| F-EXPR-03 | 式の評価結果を表示できること(`print` / `p`)。GDB 互換の書式指定子(x d u o t c f a z s)を付与できること。 |
| F-EXPR-04 | 構造体・配列型の変数は、設定に応じて整形表示(`set print pretty`)できること。 |
| F-EXPR-05 | ポインタ値には、設定に応じてシンボル注釈を付与できること(`set print address`)。 |
| F-EXPR-06 | 文字ポインタ・文字配列は書式指定 `/s` により C 文字列として読み出し表示できること。 |
| F-EXPR-07 | 変数またはレジスタへの代入ができること(`set <lvalue> = <expr>`)。 |
| F-EXPR-08 | 現在のスコープにおけるローカル変数・引数・グローバル変数の一覧と値を表示できること(`show locals|args|globals`)。 |
| F-EXPR-09 | 配列・文字列表示件数の上限(`elements`)、繰り返し要素の圧縮閾値(`repeats`)を設定・表示できること(`set print` / `show print`)。 |

### 4.8 シンボル解決

| ID | 要件 |
|---|---|
| F-SYM-01 | ルートプロセス起動時、およびそのモジュールロード時に、DbgHelp を用いてシンボル情報をロードすること。 |
| F-SYM-02 | 子プロセスのモジュールについてはシンボル解決の対象としないこと(4.9 節「制約事項」参照)。 |
| F-SYM-03 | アドレスから「関数名+オフセット(該当する場合はファイル名:行番号)」への変換ができること。 |
| F-SYM-04 | 関数名・`ファイル名:行番号` からアドレスへの変換ができること。 |
| F-SYM-05 | スタック巻き戻し(unwind)により、コールスタック・呼び出し元復帰アドレスを取得できること。 |

### 4.9 メモリリーク検出

| ID | 要件 |
|---|---|
| F-LEAK-01 | `malloc` / `calloc` / `free` にフックを設置し追跡を開始できること(`leak start`)。フック対象はルートプロセスのシンボルに限定されること。 |
| F-LEAK-02 | 追跡を停止し、フックを解除できること(`leak stop`)。 |
| F-LEAK-03 | 現在の未解放確保(サイズ・アドレス)の一覧と合計サイズを報告できること(`leak report`)。 |

### 4.10 REPL・その他

| ID | 要件 |
|---|---|
| F-REPL-01 | 対話的なコマンドライン(プロンプト `(tdb)`)を提供すること。 |
| F-REPL-02 | 未対応・書式誤りのコマンド入力に対し、処理を継続したままエラーメッセージを表示すること(REPL 自体は終了しない)。 |
| F-REPL-03 | コマンド一覧・書式のヘルプを表示できること(`help` / `h`)。 |
| F-REPL-04 | `quit` / `q` により、デバッギーを終了しデバッガ自身も終了できること。 |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NF-01 | 対応 OS は Windows(x64)とする。 |
| NF-02 | 対応アーキテクチャはデバッギー・デバッガ双方とも x64 とする(レジスタ表示・コンテキスト操作は x64 CONTEXT 構造体に基づく)。 |
| NF-03 | 実装言語は Rust とし、Win32 API 呼び出しには `windows` クレートを使用する。 |
| NF-04 | デバッガは起動時に `SeDebugPrivilege` の有効化をベストエフォートで試みること。有効化に失敗しても動作は継続すること(管理者権限で実行していない場合は無効のままとなることを許容する)。 |
| NF-05 | Windows がデバッガ自身にもアクセスを拒否する一部スレッド(OS 内部のワーカースレッド等)が存在しても、警告表示のみでデバッグ処理全体を継続できること。 |
| NF-06 | デバッグイベント待機はポーリング(タイムアウト付き)とし、待機中も Ctrl+C 転送要求を検知できること。 |
| NF-07 | ソースファイルが存在しない/読み取れない場合は、逆アセンブル表示にフォールバックすること。 |

## 6. スコープ外・既知の制約

- 子プロセス(孫プロセス以降含む)のモジュールに対するシンボル解決は行わない。子プロセス内のアドレスは生アドレスで表示され、シンボル名では表示されない。`break <関数名>` や `leak start` によるアロケータ関数フックは、いずれもルートプロセスに対してのみ有効である。
- x86(32bit)デバッギーには対応しない。
- リモートデバッグ、カーネルデバッグ、タイムトラベルデバッグには対応しない。
- ソースコードの編集・再コンパイルは対象外。
- GUI は提供せず、コンソール(REPL)のみで動作する。
